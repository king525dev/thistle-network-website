Next.js + Strapi — Part 2: Editing Your Whole Site From Strapi

Single types for page content, plus adding News articles and Gallery albums without touching code.

This is the continuation of Part 1 ("Next.js + Strapi + a Real Database — A Beginner's Guide"). Same project (Thistle Network), same database (PostgreSQL), same Strapi. In Part 1 you made the pipe work: Postgres ⇄ Strapi ⇄ Next.js. In this part you make the website's words editable by a non-technical person, and you learn the everyday workflow of publishing new content.

How this part was checked. Before writing it, I installed Strapi 5.58, built the exact content model described below, filled in some test content, and ran the Next.js project against it. The URLs, JSON responses and page results in this guide come from that real run, not from memory. One honest limit: I could not click through Strapi's admin screens in a browser, so button labels are described from the docs and may be worded slightly differently in your version. If a label doesn't match exactly, look for the closest one.

What you will be able to do by the end

  1. Change the Home page text (headline, buttons, registration cards, about text, activities, and more) from Strapi's admin panel.
  2. Change the Gallery and News page headings and messages from Strapi.
  3. Publish a News article — text, image, author, pinned or not — using only Strapi.
  4. Add a Gallery album with lots of photos and alt text using only Strapi.
  5. Understand why each of those works, so you can fix it when it doesn't.

Part 0 — Concepts for this part

You already know "collection type" and "API" from Part 1. Three new ideas make this part make sense.

0.1 Single type vs. collection type

Collection type Single type
Meaning A list of similar things One thing, there is only ever one
Example in this project News Posts, Gallery Albums, Authors Home Page, Gallery Page, News Page
Real-world analogy A spreadsheet with many rows A single settings form
API address /api/news-posts (plural) /api/home-page (singular)
Admin screen A table of entries + "Create new entry" Straight to one form

Why single types for pages? A page like "Home" only exists once. Its content (the headline, the button text, the paragraph about the organisation) is just a bunch of fields, so a single type is a form where each field is one piece of text on the page.

0.2 Components (Strapi's kind, not React's)

Careful with the word. A Strapi component is a reusable group of fields. It is for data, not for drawing anything on screen.

Think of it like a JavaScript object type you want to reuse:

// a "CTA" component is just this shape of data:
{ label: "Register to join", href: "/#registration" }

Instead of adding a label field and a href field every time you need a button, you define a CTA component once and reuse it. Components can be:

  • Single: one group of fields (e.g. the Hero block has one primaryCta).
  • Repeatable: a list of the group (e.g. the Registration block has several cards, and each card has several benefits).
  • Nested: components inside components (Registration → Card → Benefit).

0.3 Draft vs. Published (this causes most beginner confusion)

Every entry has two versions in Strapi 5:

  • Draft: what you are editing. Visitors never see it.
  • Published: the live copy. Your website only reads this one.

The two buttons at the top right of an entry do different jobs:

  • Save stores your changes as a draft.
  • Publish makes the draft the live version.

Golden rule: after any edit, you must click Publish again, or your website will not change. A single type that has never been published returns a 404 Not Found from the API.

0.4 The full journey of one sentence

When an editor changes the headline on the home page, this is what happens:

Editor types in Strapi  →  Strapi stores it in Postgres  →  Editor clicks Publish
        ↓
Next.js asks  GET /api/home-page?populate…   (lib/strapi/queries.ts)
        ↓
Strapi answers with JSON (flat, nulls for empty fields)
        ↓
mapStrapiHomePage() turns it into your own HomePageContent type (lib/strapi/mappers.ts)
        ↓
app/page.tsx passes it to <Hero content={…} /> etc.
        ↓
Visitors see the new headline

Part 2 — What changed in the Next.js project

Part 1 left some page text typed directly into components (for example the Hero headline lived inside Hero.tsx). You can't edit text from a CMS if it's welded into the code, so the project was updated. Use the new thistle-network-frontend.zip that comes with this guide (replace your old project folder, keep your .env.local).

You don't need to understand every file to continue, but understanding the pattern will make you much more capable, so here is the tour.

2.1 New types: types/home.ts and types/page.ts

These describe, in TypeScript, the words each part of the page needs:

export type HeroContent = {
  eyebrow: string;
  headline: string;
  description: string;
  primaryCta: Cta;        // { label, href }
  secondaryCta: Cta;
  supportingText: string;
};

A type is a promise about the shape of an object. HeroContent promises "whoever gives me hero content gives me exactly these fields". Strapi's field names are chosen to match.

2.2 Components now receive their words as props

Before (Part 1), Hero.tsx had the headline typed inside it. Now:

export default function Hero({ content }: HeroProps) {
  return (
    <section className="hero">
      ...
      <h1>{content.headline}</h1>
      <p className="hero-sub">{content.description}</p>
      ...

If you know basic React, this is just props — the same idea as <Button label="Click" />. Hero no longer knows or cares where the words come from.

The same was done for Registration, Events (heading only), About, Activities, FAQ (the left "committee" column), and Contact (heading).

2.3 Fallback content: data/mock/home.ts and data/mock/pages.ts

These files hold the default wording (the same text the site had before). They are used in two situations:

  1. Strapi isn't configured (no STRAPI_URL): the site still works, using these words. Great for designing without the CMS running.
  2. An editor leaves something empty in Strapi: that one piece falls back to the default text. So a half-filled page can't break the site.

2.4 The mapper: turning Strapi's JSON into your types

Open lib/strapi/mappers.ts and find this tiny helper:

function textOr(value: string | null | undefined, fallback: string): string {
  return value ? value : fallback;
}

Strapi sends null for any empty field. textOr means "use the value if there is one, otherwise use the default". The big function mapStrapiHomePage uses it everywhere:

hero: {
  eyebrow: textOr(hero?.eyebrow, defaults.hero.eyebrow),
  headline: textOr(hero?.headline, defaults.hero.headline),
  ...

The ?. is optional chaining: hero?.headline means "if hero is null/undefined, give undefined instead of crashing". If you've only used basic JavaScript this might be new — it's a safety net for exactly the "editor left it blank" situation.

2.5 The queries: what to ask Strapi for

lib/strapi/queries.ts has one function per thing the site needs:

export async function getHomePage(): Promise<HomePageContent> { ... }
export async function getGalleryPage(): Promise<PageContent> { ... }
export async function getNewsPage(): Promise<PageContent> { ... }
export async function getNewsPosts(): Promise<NewsPost[]> { ... }
export async function getGalleryAlbums(): Promise<GalleryAlbum[]> { ... }

Two details worth understanding:

populate. Strapi 5 only sends top-level text fields by default. Components, relations and images are left out unless you ask. The home page asks like this:

/api/home-page
  ?populate[hero][populate]=*
  &populate[registration][populate][cards][populate][benefits]=true
  &populate[about][populate][paragraphs]=true
  &populate[activitiesSection][populate][items]=true
  &populate[committee]=true
  &populate[eventsSection]=true
  &populate[contactSection]=true

In plain English: "include the hero block and everything directly inside it; include registration, and inside it the cards, and inside each card the benefits; …". The brackets go one level deeper each time. Nested components need to be named all the way down.

The 404 safety net. A single type nobody has published returns 404. For page text that simply means "use the defaults", so the code catches that case instead of crashing:

if (error instanceof StrapiError && error.status === 404) return null;

2.6 One helper for images: strapiMediaUrl

I tested this on a real Strapi: uploaded images come back with relative addresses like /uploads/photo_1a2b3c.jpg. A browser would look for that file on your Next.js site (port 3000), where it doesn't exist. strapiMediaUrl() in lib/strapi/client.ts adds the Strapi address in front (http://localhost:1337/uploads/...). It's called inside the mapper, so components never think about it.

2.7 lib/content.ts: one door for all content

export async function getHomePageContent(): Promise<HomePageContent> {
  return isStrapiConfigured() ? strapi.getHomePage() : mockHomePage;
}

Pages ask this file for content. It decides: Strapi (if STRAPI_URL is set) or fallback. This replaces the edit you made to app/news/page.tsx in Part 1.

2.8 The pages

app/page.tsx is now async and just passes content down:

export default async function HomePage() {
  const content = await getHomePageContent();
  return (
    <>
      <Hero content={content.hero} />
      <Registration content={content.registration} />
      ...

async + await directly inside a component only works in a Server Component (the default in Next.js). It's the superpower from Part 1: the data is fetched on the server before any HTML is sent.

The pages also export generateMetadata, which sets the browser tab title and the description search engines show, from the SEO fields you'll add in Strapi.

Part 3 — Build the page content types in Strapi

Strapi stores your content model as files in your project (src/api/... and src/components/...). The Content-Type Builder is just a friendly way to write those files. That has two consequences worth knowing:

  • The Content-Type Builder only works in development mode (npm run develop). It is switched off in production.
  • When you save, Strapi restarts itself for a few seconds. That's normal. Wait for it to come back before continuing.

Stuck or in a hurry? The zip thistle-cms-schema.zip contains the finished files for everything in this Part. Copy its src/api and src/components folders into your Strapi project's src/ folder, run npm run develop, and skip to Part 4. But it's worth doing it by hand once, because that's how you learn what Strapi is doing.

3.1 Why names must match exactly

Your Next.js code reads fields by name — hero.headline, registration.cards, activitiesSection.items. If you type Headline or head_line in Strapi, the website won't find it and will quietly use the default text. Copy the names exactly, including capital letters (this style is called camelCase: first word lower-case, later words start with a capital).

3.2 Create the components first

Components must exist before you can use them inside other things, so we build from the smallest upward.

In the Strapi admin: Content-Type Builder → Components → Create new component. For each one: choose a Category (type a new name the first time), a Display name, and any icon, click Continue, then add fields (Add another field), then Finish and Save.

Category + display name decide the component's internal ID. Category shared + name CTA becomes shared.cta. Use exactly the category names shared and home below.

Category shared

Display name Fields (name → type)
CTA label → Text (Short), required · href → Text (Short), required
Text Item text → Text (Long), required
Page Header eyebrow → Text (Short) · title → Text (Short), required · description → Text (Long)

"CTA" = call to action, i.e. a button: its label and where it links.

Category home

Display name Fields
Hero eyebrow (Short text) · headline (Short text, required) · description (Long text) · primaryCta → Component, use existing shared.cta, single · secondaryCta → Component, shared.cta, single · supportingText (Short text)
Audience Card audienceKey → Enumeration with values aspiring and current, required · tag (Short) · heading (Short, required) · description (Long) · benefits → Component, shared.text-item, repeatable · ctaLabel (Short) · ctaUrl (Short, required)
Registration eyebrow (Short) · heading (Short) · cards → Component, home.audience-card, repeatable
Events Section eyebrow (Short) · heading (Short)
About eyebrow (Short) · lead (Long) · paragraphs → Component, shared.text-item, repeatable · tagline (Short)
Activity title (Short, required) · description (Long) · icon → Enumeration: career, community, events, partnerships, visibility, education (required)
Activities Section eyebrow (Short) · heading (Short) · items → Component, home.activity, repeatable
Committee eyebrow (Short) · heading (Short) · blurb (Long)
Contact Section eyebrow (Short) · heading (Short)

Create them in this order so each dependency already exists: Audience Card before Registration, Activity before Activities Section.

How to add a component field (e.g. primaryCta inside Hero): click Add another field, pick the Component tile, choose Use an existing component, give the field its Name (primaryCta), pick shared.cta from the dropdown, and choose Single component (or Repeatable component for lists). Click Finish.

Enumeration values: when adding an Enumeration field, type each allowed value on its own line in the Values box, exactly as written (lower case).

Part 5 — Edit the Home page content

In the admin sidebar, open Content Manager. Under Single Types click Home Page. You'll see one form with an expandable section per component.

Every field is optional by design. Anything you leave empty keeps the website's default text. You can fill in just the parts you want to change.

5.1 Hero

Open hero. Fields:

  • eyebrow: the small label above the headline
  • headline: the big title
  • description: the paragraph underneath
  • primaryCta: the main button → label (button text) and href (where it goes)
  • secondaryCta: the second (outlined) button
  • supportingText: the small line under the buttons

Where do hrefs point?

  • To a place on the home page: /#events, /#registration
  • To another page on your site: /gallery
  • To another website: the full https://… address (these open as normal links)

5.2 Registration cards

Open registration: set eyebrow and heading. Under cards click Add an entry to add each card.

For each card:

Field What it does
audienceKey aspiring or current. This also chooses the look: aspiring is the light card with the dark button; current is the dark card.
tag Small label at the top ("For Aspiring Apprentices")
heading Card title
description Short paragraph
benefits Click Add an entry for each bullet point; type it into text
ctaLabel Button text
ctaUrl Required. Where the button goes (your Google Form link, for example)

Add two cards (one aspiring, one current). If you add no cards at all, the defaults are used. If you delete cards after adding some, the site shows exactly the ones you left.

5.3 Events section, Committee, Contact section

Just eyebrow and heading (Committee also has a blurb). Note: this only changes the headings. The event cards themselves are not in Strapi yet (see Part 10).

5.4 About

eyebrow, lead (the large sentence), paragraphs (add one entry per paragraph), and tagline.

5.5 Activities

eyebrow, heading, and items: one entry per tile, with title, description and an icon chosen from the list (the icons are drawn by the website; you pick which one).

5.6 SEO

seoTitle becomes the browser-tab title and what Google shows as the headline. seoDescription is the grey text under it. If you leave seoTitle empty, the site uses "Thistle Network | Connecting Apprentices Across Scotland".

5.7 Save, then Publish

Click Save, then Publish (top right). Remember the golden rule.

5.8 Test the API yourself

In a terminal (or paste into a browser's address bar):

curl -g "http://localhost:1337/api/home-page?populate[hero][populate]=*&populate[registration][populate][cards][populate][benefits]=true&populate[about][populate][paragraphs]=true&populate[activitiesSection][populate][items]=true&populate[committee]=true&populate[eventsSection]=true&populate[contactSection]=true"

5.9 See it on the website

Open http://localhost:3000. In my test (headline "Edited in Strapi!", button "Join now", one registration card, one activity), the page showed exactly those, while everything I'd left empty — the about text, committee column, contact heading — still showed the defaults. That's the fallback working as designed.

"I don't see my change!" The website remembers Strapi's answer for up to 60 seconds (that is the revalidate setting in lib/strapi/client.ts; more on it in Part 9). Wait a minute and refresh. To see changes instantly while learning only, change options.revalidate ?? 60 to ?? 0 in that file, and change it back later.

Part 7 — Publish a News article using only Strapi

This is the everyday job your committee will do. No code, no deployment.

Step 1 — (Optional) add the image to the Media Library first

Media Library → Add new assets → From computer (or drag and drop). After upload, click the image to open its details and fill in:

  • Alternative text — describe the picture for people who can't see it. Example: "Apprentices chatting at the Glasgow summer meet-up". It also helps search engines.
  • Caption — optional.

Good habit: write alt text every single time. The website displays it automatically wherever the image is used.

Keep photos reasonably sized (a couple of MB at most) so the site stays fast.

Step 2 — Create the entry

Content Manager → News Post → Create new entry.

Field What to enter
title Optional headline for the post
body The message. Plain text only for now (no bold or links); blank lines are not shown on the site, so keep it to a short paragraph
pinned Turn on to keep this post at the top of the feed (see below)
image Optional: pick from the Media Library or upload now
author Choose an existing Author (or create one in Author)

Step 3 — Save, then Publish

Save, then Publish. The publishedAt date shown on the post (e.g. "2 days ago") is the moment you click Publish.

Step 4 — Check it

  • API: http://localhost:1337/api/news-posts?populate[image]=true&populate[author][populate][profileImage]=true&sort=publishedAt:desc
  • Website: http://localhost:3000/news (allow up to 60 seconds)

In my test, one published post titled "Hello from Strapi" (pinned, with an image and the author "Thistle Network") appeared with the Pinned badge, its text, and its image loaded from http://localhost:1337/uploads/….

How the feed orders posts

The website puts pinned posts first, then everything else newest first. To unpin: edit the post, turn pinned off, Publish again.

Editing, hiding and deleting

  • Edit: change the entry, Publish again.
  • Hide without deleting: open the entry and Unpublish. It disappears from the site but you keep it as a draft.
  • Delete: removes it permanently.

What you do NOT do in Strapi

The like counts, emoji reactions and comments on posts are not stored in Strapi. They are demo-only buttons today (they reset on refresh). A later application backend with its own database will store them. Strapi is for the article itself.

Part 8 — Add a Gallery album using only Strapi

Content Manager → Gallery Album → Create new entry.

Field What to enter
title e.g. "Summer Meet-Up — Glasgow"
date The date of the event (albums are sorted newest first by this)
tagline Optional short note, e.g. "60+ attendees"
location e.g. "Glasgow"
attendeeCount Optional number, used if there is no tagline ("60+ attendees")
coverImage A representative photo (stored for future use; the Gallery page doesn't display it yet)
images All the album's photos

Adding many photos at once

In the images field click to add assets, then choose From computer and select or drag many files at once. You can usually drag thumbnails to reorder them, and the website shows them in that order.

Give every photo alt text

Open Media Library, click each new photo, fill Alternative text (what's in the picture) and, if you like, Caption. The site uses:

  • the alt text for screen readers and when an image fails to load,
  • the caption as the small text under the enlarged picture in the lightbox.

Photos with no alt text still show, but they're less accessible. Make it a team rule.

Save, Publish, check

Save → Publish. Then check http://localhost:3000/gallery. The metadata line under the album title reads date · location · tagline (or "N+ attendees" if you left the tagline empty). Click a photo to open the lightbox; use ←/→ and Esc.

In my test, an album with two photos appeared with both images loading from http://localhost:1337/uploads/… and their alt text present.

Part 9 — Why changes take up to a minute (and when they don't)

In lib/strapi/client.ts:

next: { revalidate: options.revalidate ?? 60 },

This is a Next.js caching instruction: "remember Strapi's answer for 60 seconds; after that, fetch a fresh copy in the background." Why? Without it, every visitor would trigger a request to Strapi, which is slow and expensive. With it, a thousand visitors in a minute cost one request.

  • While learning: set it to 0 temporarily to see edits instantly.
  • In real use: 60 seconds is a good balance. A more advanced approach (called on-demand revalidation, Strapi sending a webhook to Next.js when you click Publish) updates the site instantly. That's a topic for a later part.
  • Building for production: npm run build fetches content to pre-build pages, so Strapi must be running (and reachable) when you build. If it isn't, the build will fail with a "fetch failed" error.

Part 12 — Quick checklist & practice ideas

Publishing a news article: Media Library (upload + alt text) → News Post → Create new entry → fill fields → Save → Publish → check /news.

Adding an album: Gallery Album → Create new entry → title/date/location → upload photos → alt text → Save → Publish → check /gallery.

Editing a page: Content Manager → Single Types → pick the page → edit → Save → Publish.

Practice:

  1. Change the home page headline and the primary button's link to your own Google Form.
  2. Add a seventh activity with the partnerships icon.
  3. Rename the News page title to "Latest from Thistle".
  4. Publish a news post with pinned on, then another one without, and see which is first.
  5. Add a second current registration card and look at how the layout copes. (Lesson: content can change layout, so editors should check the live page.)
  6. Clear the committee.heading field, Publish, and confirm the default heading comes back on the site.

│   ├── news-post/         ← collection type
│   └── gallery-album/     ← collection type
└── components/
    ├── shared/            cta, text-item, page-header
    └── home/              hero, registration, audience-card, events-section,
                           about, activities-section, activity, committee, contact-section

Each content type is a schema.json describing its fields — exactly what the Content-Type Builder writes when you click. Commit these to git so your teammates get the same model.

Appendix B — Words you met in this part

Term Meaning
Single type A content type with exactly one entry (a page's settings)
Component (Strapi) A reusable group of fields, optionally repeatable or nested
Repeatable A component you can add several of (a list)
Enumeration A field limited to a fixed list of values
Draft / Published Working copy vs. the live copy the website reads
Populate Telling Strapi to include components/media/relations in the response
Fallback Default text used when Strapi has nothing for a field
Revalidate How long Next.js remembers an answer before checking again
Optional chaining (?.) Safe property access that gives undefined instead of crashing
Server Component A component that runs on the server and can await data directly
